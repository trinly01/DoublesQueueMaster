fix: completedMatchesResetAt survives offline reset + isFreshState zeroing

Three bugs fixed in the completed matches reset propagation:

1. isFreshState branch (root cause): when an offline admin resets and
   comes back online, their state looks "fresh" (empty), triggering the
   isFreshState branch which zeroed completedMatchesResetAt. This wiped
   the reset epoch, allowing old completed matches to resurrect from
   the server. Fix: preserve completedMatchesResetAt and its per-field
   stamp when non-zero (distinguishes local reset from truly fresh state).

2. isRemoteReset branch: did not copy completedMatchesResetAt from
   server. Fix: use Math.max(local, server) so the most recent reset
   always wins, with the winning per-field stamp preserved.

3. Non-privileged branches (useClubData + useCloudSync): did not copy
   completedMatchesResetAt from server. Fix: copy it alongside the
   other checkpoint timestamps.

4. saveState() local purge: added a safety net that purges completed
   matches older than completedMatchesResetAt on every saveState call.
   No-op when resetAt=0 (99% of sessions).

Scenario fixed: Admin A resets offline, Admin B completes a match
online. When Admin A returns, only the new match survives (was: all 6
matches resurrected).
