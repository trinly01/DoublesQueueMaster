# UI Perf — Data Volume × Per-Item Cost (ClubPage)

## Row counts (realistic club: 10–100 players)
1. **HIGH — No virtualization on any main list.** `PlayerList.vue:3-5` renders every player; `players` = ALL non-deleted registered players, unbounded dict (`ClubPage.vue:1836-1851`). Queue list same component (`ClubPage.vue:408,1070`). Matches: `v-for` over `filteredMatches`/`desktopMatches`/`waitingMatches` (`ClubPage.vue:684,755,898,1373,1516`). Only `LeaderboardDialog` virtualizes (`:244,:420`). 100 players → ~100 PlayerCards × ~15-20 live components each (q-btn/q-tooltip/q-chip/q-menu per row — `PlayerCard.vue:187-290`, `PlayerList.vue:34-247`) ≈ 2k instances; full re-render per mutation.
2. **HIGH — Single reactive blob → whole-page cascade.** `MatchmakingApp.state` is one `reactive()` (`matchmaking.ts:98`). `players` computed spreads every player (`ClubPage.vue:1839-1850`) so ANY single-player field write (60s rating poll `useCloudSync.ts:1130-1133`, any check-in/match mutation) rebuilds all N objects → new array identity → `displayPlayers` re-sorts O(n log n) (`PlayerList.vue:368-424`, sortBy always set, default 'matchesPlayed') → every PlayerCard re-renders. Same invalidation hits `queue` (`:1967-2076`, units+sorts), `matches` (`:2093-2145`, `computeWinProbability` per match + reads players dict), `filteredMatches` sort (`:4110-4154`), `busyPlayers`, `linkedPairColors` (`:1937`), `avoidedByMap` (`:1956`), `displayMatches` builders (`:3894-3939`).
3. **HIGH — History filters render unbounded rows.** `completedMatchViewModels` maps ALL `completedMatches` (cap 500, `matchmaking-core.ts:233`) with `computeWinProbability` each (`ClubPage.vue:4025-4070`), then renders every row (`:754-894` desktop, `:1372-1512` mobile) — no pagination. `cancelled` maps `activeMatches` tombstones retained 30 days (`gcTombstones`, `matchmaking-core.ts:366-383`) — grows with club volume. 'edited' also builds all 500 VMs (`:4092-4100`).
4. **MED — Mobile keep-alive mounts all 3 tab panels** (`ClubLayout.vue:140-160`). Verified Vue 3.4 keep-alive does NOT pause render effects (only lifecycle hooks skip — `runtime-core.cjs.js:2699`); hidden players/queue/matches lists keep DOM + re-render on every state change. `animated` adds transition cost.
5. **MED — Desktop renders 3 columns at once** (`ClubLayout.vue:65-92`): players + queue + matches PlayerLists simultaneously; a queued player renders in BOTH lists → duplicate DOM + duplicate avatar `<img>` per row.
6. **MED — Per-row component weight.** PlayerCard: ~6 q-tooltip + ~4 q-btn + 2 rating chips + up to 4 floating badges per row (`PlayerCard.vue:49-178,187-290`). MatchCard: 2 chips+tooltips per player ×4 players + MatchMetaChips (`MatchCard.vue:51-75,177-201,206-224`; `MatchMetaChips.vue` ~10 conditional chips).
7. **MED — 1s ticker.** Shared `useNowTicker` interval (`useNowTicker.ts:10-17`) re-renders every in-progress MatchCard each second for `elapsed` (`MatchCard.vue:463-472`); also MatchResult in dialog (`MatchResult.vue:371-383`).
8. **MED — Infinite CSS animations on rows:** self-row pulse (`PlayerCard.vue:471-482`), link/avoid candidate pulses (`:529-557`), self-match pulse (`MatchCard.vue:488-518`), live-dot pulse (`:572-592`) — constant repaint while visible.
9. **MED — Mutation cost outside render:** `saveState()` runs 7 enforcement passes on EVERY mutation (`matchmaking.ts:173-338`: oneMatchPerPlayer/Court/Concurrency/QueueMatch/orphan cleanup/2× dedup/GC/checkpoint purges/caps), then serializes whole state (≤500 completedMatches) via requestIdleCallback→LocalStorage (`:115-161`). Debounced cloud push re-serializes+PATCHes the whole appState blob 1.5s after edits (`useCloudSync.ts:1069-1076,425-442`); realtime delivers the whole blob per update (`:880-925`).
10. **MED — LeaderboardDialog open = 4 parallel heavy fetches** (`ClubPage.vue:3737-3744`): club 1000 matches (worker replay, `useLeaderboard.ts:107`), **global 1000 matches + `replayMatchesForRanking` INLINE on main thread** (`ClubPage.vue:3099`), myMatches 500 + `replayMatches` inline (`:3312`), duo up to 5000 matches (`useDuoLeaderboard.ts:33-34,72-95`, worker). Main-thread replays block UI on open.
11. **MED — SettingsDialog 'club' tab:** renders ALL members in 3 lists with non-lazy avatar `<img>` (no `loading` attr — `SettingsDialog.vue:627,733,862`; lists `:619-963`); `adminMatchStats` rescans completedMatches+activeMatches+200 logs per change (`useClubMembers.ts:97-171`). Action Logs: ≤200 rows rendered fully when expansion opens (`SettingsDialog.vue:404-487`; cap `matchmaking-core.ts:300`) — ~10-branch icon ternary + `formatDate` + `Object.entries(details).map` per row.
12. **MED — Feedback list unbounded:** `getClubFeedback` fetches ALL `report_player` rows, no limit (`playerReport.ts:315-335`); `sortedFeedback` sorts all + `getClubFeedbackReasons` does `.find()` per key per row (`SettingsDialog.vue:1315-1328,985-1050`).
13. **LOW — Avatars:** `player.avatar` = external `${likhaUrl}/assets/<id>` (`ClubPage.vue:3465`); `PlayerAvatar` img has `loading="lazy"` (`PlayerAvatar.vue:34`) so offscreen rows defer fetch, but all img elements still mount; masked fallback hits `cdn.quasar.dev` (`:97-100`). ~N requests per list first paint (cache-hit across duplicate rows).
14. **LOW — Per-row O(n) helpers:** `avoidStateFor` does `players.find` per row while avoid mode armed → O(n²) (`PlayerList.vue:453-455`); `isPlayerSelected` `.some` per row (`:426-428`); `isMatchDuprReady` can `Object.values(players).find` per member (`ClubPage.vue:2206-2227`) — only inside lazy q-menu; `getDuprStatus/getDuprError` ~6 calls/completed row (`:782-783,802-804,816-819`), `duprSubmissionMap` rebuilds on submissions change (`:1815-1821`).
15. **LOW — Watcher overhead:** deep watch on queue array traverses all queue objects per change (`ClubPage.vue:3810-3825`); duprId join watcher builds string over all players per change (`:1855-1865`); `queueStats` = 5×queue scans (`:3941-3963`); `filteredMatches.indexOf(match)` per click (`:692-696,916-920,1533-1536`).
16. **INFO — No charts on club page:** ECharts only in `PlayerPage.vue:1733+`; `MemberMatchStats.vue` is chips only; LeaderboardDialog uses q-virtual-scroll.
17. **INFO — Dialog data is mostly lazy:** leaderboards fetch on dialog open not mount; settings refreshes members only on 'club' tab (`ClubPage.vue:3731-3735,3861-3871`); matchKey retry bounded 6×4s (`:2880-2893`); ratings poll 60s + staleness poll 20s (`useCloudSync.ts:1130-1140`).

## Top data-side jank drivers
Unvirtualized full-list rendering (up to ~100 PlayerCards, up to 500 MatchResult rows) × whole-state invalidation cascade (any mutation re-renders all lists) × unbounded completed/cancelled history × mobile keep-alive hidden panels still re-rendering × 1s ticker on in-progress cards.
