# UI Perf — Network Request Patterns (ClubPage)

## Findings
1. **HIGH — No-cache mount gates first render on the heaviest request.** `clubLoadingState='loading'` → full-screen spinner (`ClubPage.vue:4-10`) until the single biggest read — club row + `appState` blob + players/admins/moderators M2M deep (`useClubData.ts:407-447`) — resolves; with cache it paints instantly + `dataFetchBar` (`useClubData.ts:396-402`). ALL later mount fetches are `await`-chained behind it (`ClubPage.vue:3613-3636`).
2. **HIGH — Every `loadClubData` unconditionally arms a full-blob push ~1.5s later.** `MatchmakingApp.persist()` at `useClubData.ts:997` (any non-empty `club.players`) → `saveState()` stamps `lastModified=now` + fires `onStateChange` (`matchmaking.ts:333-337`) → `debouncedCloudSync` (`useCloudSync.ts:1069-1078`) → `performCloudSync` = light ts read + FULL probe read (`appState,date_updated`, `:376`) + CAS PATCH of whole blob (`:429`). Fires on mount, every `doResumeSync` (focus/visibility/pageshow, `ClubPage.vue:3554-3571`, `useCloudSync.ts:978-993`), role-change refresh (`:658`), poll fallback (`:1057`), join reload (`useClubData.ts:257`). Each push re-broadcasts the blob to every club subscriber.
3. **HIGH — appState blob ≈0.5–1.5MB JSON, moved 2–3× per sync + once per realtime event per client.** Contents: players dict w/ `history.playedWith/playedAgainst` O(roster²), queues, activeMatches, `completedMatches`≤500 (~1KB each, `matchmaking-core.ts:233`), `completedMatchIds`≤2000 (`:236`), `actionLogs`≤200 (`:300`), settings+checkpoints (`:144-199`). Downloaded on every loadClubData/probe/pull; uploaded on every PATCH; pushed over WS to all subscribers per club update (`useCloudSync.ts:880-925`).
4. **HIGH — Cold mount ≈10–11 REST + 2 WS, incl. duplicates + possible 2nd full club read.** Burst after `await loadClubData`: `readMe` (`ClubPage.vue:3592`), `payment_settings` (`:3588`→`usePayment.ts:13`), feedback = `report_player` (NO limit, `playerReport.ts:319`) + `readUsers` batch (`:285`), `dupr_settings` (`useDupr.ts:134`), `completed_match` keys ×2 — direct (`:3633`) AND watcher→`fetchKeysUntilMapped` (`:2899-2905`, retries ≤6×4s `:2881-2893`), `dupr_submission` (`useDupr.ts:214`), club players M2M ratings read (`ClubPage.vue:3410` via `:2899-2904`), conditional DUPR ratings-flow POST (`useDupr.ts:783-813`), WS subs club+dupr_submission (`useCloudSync.ts:880`, `useDupr.ts:273`). Non-member adds join write + SECOND full `loadClubData` (`useClubData.ts:257`, `clubMembership.ts:42-51`). Privileged adds +3–4 sync requests (finding 2).
5. **MED — Steady-state idle ≈4 REST/min/client; degraded ≈6/min.** 20s staleness poll → 1 lightweight `json()` ts read/tick, skipped only if realtime msg <20s old (`useCloudSync.ts:1002,1017,1021-1028,1138-1140`) = 3/min; 60s ratings poll → club players M2M read (`:1130-1133`→`ClubPage.vue:3410`) = 1/min. If light read errors AND realtime dead → FULL `loadClubData` fallback every 20s (`:1051-1061`). Realtime retry backoff caps 30s, unbounded (`:861-870`).
6. **MED — `completedMatches.length` watcher fans out per completion on every client.** Any change (mount merge, realtime/pull, local score) → `fetchKeysUntilMapped` chain + `refreshPlayerRatings` (`ClubPage.vue:2899-2905`); retriggers stack (no cross-chain dedup).
7. **MED — Per-push cost = 3–4 requests + ~2 blob transfers.** `readServerClubRow` probe ALWAYS reads full `appState` before PATCH (`useCloudSync.ts:203-223,369-442`); ts-read only skips the optional full read (`:253-280`); CAS conflict → +1 probe +1 PATCH (`:444-476`). Busy admin ≈1 sync/1.5–3s → tens of req/min + tens of MB/min club-wide.
8. **MED — Realtime = full blob per update × every subscriber + heavy per-msg CPU.** `fields:['appState',…]` (`useCloudSync.ts:886-894`); echo check runs only AFTER payload received (`:664-674`); `applyServerMatchmaking`→`collectionEqual`/`jsonEqual` JSON.stringify per collection (`cloudSyncHelpers.ts:294-332`) + `persistSilently`→synchronous `LocalStorage.set` whole state (`matchmaking.ts:148-161`, `useCloudSync.ts:827`).
9. **MED — dupr_submission stream: refetch-all per event + 10s self-heal.** Every WS msg → `fetchSubmissions` limit-500 (`useDupr.ts:285-289`); stream end → fetch + reconnect @10s (`:293-304`) ≈≤6/min flapping.
10. **MED — Error paths amplify the heaviest request.** Moderators-field failure retries the ENTIRE big read without moderators (`useClubData.ts:448-490`). 401 interceptor: single-flight refresh + 1 retry/req (`likhaClient.ts:156-176`); dead session → mount burst + polls become 401→refresh→fail until `handleAuthError`→logout (`useAuth.ts:122-134`). `pagehide` fires immediate `performCloudSync` (`useCloudSync.ts:1113-1121`).
11. **LOW — Dialog fetches bounded but heavy on open.** Leaderboard = 4 parallel fetches incl. `completed_match` limit-1000 `['*','players.*']` + duo ≤10×500 paged (`ClubPage.vue:3737-3744`, `useLeaderboard.ts:82-94`, `useDuoLeaderboard.ts:72-95`). Settings 'club' tab → `refreshClubInfo` (60s TTL) + `refreshClubMembers` full M2M (`ClubPage.vue:3731-3735,3861-3864`). QR scan → readUsers→joinClub→refreshClubMembers sequential (`AddPlayerDialog.vue:853-903`).
12. **INFO — "players M2M loop" is CPU-only.** `useClubData.ts:966-996` iterates `club.players` w/ `Object.values(players).find` per member = O(members×players) local merge; M2M data already in the one big read — zero extra requests. PlayerList/MatchCard/PlayerCard/dialogs make NO network calls (only `AddPlayerDialog.vue:853`).

## Request counts
| Scenario | REST reqs | WS msgs | Notes |
|---|---|---|---|
| Cold mount (member, warm cache) | ~10–11 (+3–4 privileged sync; +2–3 non-member incl. 2nd club read) | 2 subs | 1st render instant w/ cache; ~2 completed_match reads |
| Steady-state 1 min (idle, realtime quiet) | ~4 (3 light polls + 1 ratings) | 0 | degraded: +3 full reloads/min if realtime dead |
| Active match-making 1 min | ~30–40 on acting device + N×blob broadcasts | 1 full-blob msg per PATCH × subscribers | each sync = light+probe+PATCH ≈2 blob transfers |

## UI-blocking surface
Only no-cache mount spinner (`ClubPage.vue:4-10`) + main-thread merge/serialize cost block rendering; player/match actions are local+debounced (instant). Network-gated: `busyMemberOps` row disable (`useClubMembers.ts:173-206`), dialog spinners, cosmetic ajax bars (`ClubPage.vue:95-107`). Biggest remaining "hang" = finding 1 + main-thread `saveState`/merge/`LocalStorage.set` on ~1MB state.

## Top recommendations (for fix debate)
- Gate `useClubData.ts:997` `MatchmakingApp.persist()` behind an actual-change check (use `persistSilently()` when player merge changed nothing) — kills the guaranteed push-per-load.
- Skip the pre-write `readServerClubRow` full-blob probe when the lightweight timestamp already proved no concurrent write.
- Dedupe the mount `completed_match` fetch (direct call + watcher chain).
- Field-slim realtime `appState` subscription or add a changed-collections hint to avoid full-blob delivery per update.
