# 07 — Naming & Conventions

## Collections

Prefix **`book_`**, singular snake_case, plural only where the domain
demands it. Keeps booking collections grouped in Studio nav and
impossible to confuse with DinkMatch's `club_*`/matchmaking tables.

| Collection | Purpose |
|---|---|
| `book_tenants` | venue/business |
| `book_tenant_users` | staff junction (tenant ↔ directus_users + role) |
| `book_sport_types` | sport catalog |
| `book_courts` | bookable units |
| `book_opening_hours` | weekly schedule |
| `book_closures` | date exceptions / maintenance |
| `book_bookings` | reservation header |
| `book_booking_slots` | per-court time pieces of a booking |
| `book_payments` | money records |
| `book_payment_proofs` | proof-of-payment uploads |

Future additions follow the same pattern: `book_rates` (time-based
pricing), `book_promotions`, `book_memberships`, `book_reviews`.

## Field conventions

- FKs named after the entity: `tenant`, `court`, `booking`, `customer`,
  `payment`, `sport` — Directus shows them as "Tenant", "Court" etc.
- Timestamps: `created_at`/`updated_at` (Directus defaults);
  event stamps explicit: `paid_at`, `reviewed_at`, `checked_in_at`,
  `cancelled_at`.
- Money: `price`, `amount`, `subtotal`, `platform_fee`, `total`,
  `tenant_payout` — decimal PHP.
- Statuses: lowercase snake strings (`pending_payment`, `in_progress`
  avoided — use `pending`/`confirmed`/`completed`).
- Booleans: `is_*`/`has_*`/`auto_*` (`auto_confirm_payments`,
  `all_day`).
- `sort` integer for manual display ordering.
- `settings`/`metadata` JSON catch-all on tenant for future knobs.

## Booking reference format

`BK-YYYY-NNNN` — e.g., `BK-2026-0042`.

- Year-scoped sequence resets annually (easy for tenants to eyeball).
- Generated by Flow (`likha_sql` next-number pattern, same as Mitmit's
  `MIT-YYYY-NNNN` order codes).
- Unique index on `ref`. Customer-facing everywhere; internal uuid
  stays the API key.

## Status vocabularies (single source — use everywhere)

```
book_tenants.status:        pending | active | suspended
book_courts.status:         active | maintenance | inactive
book_sport_types:           (catalog, no status)
book_bookings.status:       pending_payment | confirmed | checked_in
                            | completed | cancelled | rejected
                            | no_show | expired
book_bookings.payment_status: unpaid | pending_verification | paid
                            | refunded | failed
book_booking_slots.status:  held | confirmed | released | cancelled
book_payments.status:       pending | paid | failed | refunded | expired
book_payments.method:       gcash | maya | qrph | card | bank
                            | cash | xendit_invoice
book_payment_proofs.status: pending | approved | rejected
book_tenant_users.role:     owner | manager | front_desk
```

## Customer-facing URLs (Quasar routes)

```
/book                          venue discovery
/book/v/:slug                  venue page
/book/v/:slug/book             booking grid
/book/checkout                 details + payment
/book/confirmation/:ref        success + QR
/book/my                       my bookings
/book/my/:ref                  booking detail
```

Venue slugs: lowercase-hyphen (`siklab-pickleball`), unique, set at
tenant creation — never change (it's in printed QR codes).

## Language & tone

- Customer UI: plain Filipino-English friendly ("Book a court",
  "Awaiting payment verification", "Show this QR at the venue").
- Tenant UI (Studio): functional labels, helpful field notes —
  tenants are small-business owners, not software people.
- Internal/docs: precise technical English.
